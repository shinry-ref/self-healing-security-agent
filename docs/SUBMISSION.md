# アンチボディ（Antibody）— 応募説明文

> 第5回 Agentic AI Hackathon 提出用。フォームにそのまま貼れる形でまとめています。

---

## ひとことで

**AIエージェントが自分で攻撃して脆弱性を「実証」し、Vertex AI（Gemini）で修正案を生成、適用して、同じ攻撃をもう一度かけて「今度は防げる」ことまで証明する** — 攻撃→修復→再証明の自己修復ループをリアルタイムに可視化する、自己修復型のセキュリティ診断エージェント。

---

## 対象とするユーザー像

- **自社 Web アプリを持つ中小・スタートアップの開発チーム**で、専任のセキュリティ人材がいない。
- 外部ペンテスト（脆弱性診断）は**高額・時間がかかる**ため、気軽に・継続的には回せない。
- セキュリティに不安はあるが、**何がどう危ないのか、どう直せばいいのかが分からない**開発者。
- CI/PR のたびに**自分のアプリの安全性を自動で確かめたい**チーム、またはセキュリティを学びたい個人。

## 課題

1. **脆弱性診断は専門性が高く、外注は高額で遅い。** 日常的に回せない。
2. 「脆弱性があります」と指摘されても、**どこが・なぜ危険で・どう直すか**が具体的に分からない。
3. 修正しても、**本当に防げるようになったのか確証が持てない**（直したつもり問題）。
4. 従来のレポートは静的で、**実際に攻撃されたら何が起きるのかの実感がなく**、優先度を判断しづらい。

## ソリューション

**アンチボディ**は、AIエージェントが次の自己修復ループを自律的に回し、その過程をダッシュボードで可視化する。

1. **攻撃（実証）** — 対象サイトに本物の HTTP リクエストで侵入し、脆弱性を突いて情報を抜く。
2. **原因特定** — なぜ突破できたのかを判断し、原因箇所を特定する。
3. **修正生成** — **Google Cloud の Vertex AI（Gemini 2.5 Flash）** が、脆弱性ごとに安全な修正案を生成する。
4. **適用／提示** — コードが分かる対象なら実際に修正を適用し、分からない対象なら修正案（対策方針）を提示する。
5. **再証明** — 同じ攻撃をもう一度実行し、**今度は弾かれること**を実証する。

「指摘」で終わらず、**実際に突破してみせ、直し、もう一度攻撃して防御を証明する**ところまでを一気通貫で見せるのが核心。

## 特徴

- **本物の攻撃で実証する** — 机上の指摘ではなく、実際に侵入して「パスワード無しで管理者ログイン成功」などの結果を示す。レポートには**実行した攻撃（パス・入力・結果）**も残す。
- **自己修復ループの可視化** — 侵入マップ（攻撃者→侵入口→データ）、思考ログ、進捗、最終レポートをリアルタイムに表示（SSE 配信）。
- **Vertex AI（Gemini）が修正案を生成** — CWE/OWASP に沿った修正を脆弱性ごとに生成。Cloud Run の**サービスアカウント認証（鍵レス）**で呼ぶため、API キーを持たず漏洩リスクがない。
- **2つの運転モード**（相手のコードが分かるかで出し分け）
  - **修正案**：コードが分からないリポジトリ向け。侵入を実証し、修正案（対策方針）を提示（差分は出さない・状態は変えない）。
  - **自律修正**：コードが分かるリポジトリ向け。実ソースを書き換えて（公開環境では対象の安全な実装に切替えて）、再攻撃で防御を証明。
- **自律実行** — 「診断開始」を押すと全脆弱性を自動で巡回し、最後にレポートを一括提示する。
- **合法性の担保** — 攻撃できるのは**許可リスト（完全一致）に載せた対象だけ**。任意の外部URLは実行せず 403 で弾くため、公開しても第三者の踏み台にならない。
- **9種の脆弱性に対応**（プラグイン方式）— SQLi / XSS / 認証の甘さ / アクセス制御不備 / 設定ミス / パストラバーサル / コマンドインジェクション / JWT改ざん(alg=none) / SSRF。
- **対象アプリ設定の外出し**（`antibody.config.json`）— エンドポイントやソース対応表を対象リポジトリ側に置けるようにし、将来の汎用スキャナ化への第一歩とした。

## 使用した Google Cloud 技術

- **Vertex AI（Gemini 2.5 Flash）** … 脆弱性ごとの修正案・対策方針の生成（サービスアカウント認証の鍵レス）。
- **Cloud Run** … frontend / agent / target の3サービスをコンテナでホスティング（ゼロスケール）。
- **Secret Manager** … 制御トークン・署名鍵を安全に注入。

## 構成（モノレポ・3層）

| ディレクトリ | 技術 | 役割 |
|---|---|---|
| `target/` | Next.js (TS) | 診断対象の EC サイト（NEKO MART）。9種の脆弱性をプラグイン方式で組込 |
| `agent/` | Python / FastAPI + Vertex AI | 偵察→攻撃→修復→再証明を自律実行。進行を SSE 配信 |
| `frontend/` | Next.js (TS) + D3-force | ダッシュボード（侵入マップ・思考ログ・進捗・レポート） |

## 今後の展望（正直な線引き）

現状は自己修復ループの**実証デモンストレーター**で、検出は既知9種の攻撃に基づく。任意のリポジトリに置くだけで**未知の脆弱性まで自動検査する汎用スキャナ**（DAST-lite）は今後の課題。偵察のクローラ化と対象設定の外出しは、その第一歩として実装済み。
