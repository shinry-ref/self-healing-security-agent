# アンチボディ（Antibody）— 応募説明文

> 第5回 Agentic AI Hackathon 提出用。フォームにそのまま貼れます。

## ひとこと
**AIエージェントが自分で攻撃して脆弱性を実証し、Vertex AI（Gemini）で修正案を生成・適用し、同じ攻撃をもう一度かけて「今度は防げる」ことまで証明する** — 攻撃→修復→再証明の自己修復ループを可視化する、自己修復型セキュリティ診断エージェント。

## 対象ユーザー
専任のセキュリティ人材がいない中小・スタートアップの開発チーム。外部診断は高額・遅く日常的に回せない。「何がどう危なく、どう直すか」が分からず、修正しても防げた確証が持てない開発者。

## 課題
1. 脆弱性診断は専門性が高く、外注は高額・遅い。
2. 指摘されても **どこが・なぜ・どう直すか** が分からない。
3. 直しても **本当に防げたか確証が持てない**。

## ソリューション
AIエージェントが次の自己修復ループを自律実行し、ダッシュボードで可視化する。

**攻撃（実証）→ 原因特定 → Vertex AI(Gemini)が修正生成 → 適用/提示 → 再攻撃で防御を証明。**

「指摘」で終わらず、**実際に突破し、直し、もう一度攻撃して防御を証明する**のが核心。

## 特徴
- **本物の攻撃で実証**：実際に侵入し「パスワード無しで管理者ログイン成功」等を提示。レポートに攻撃の実行内容（パス・入力・結果）も残す。
- **Vertex AI(Gemini)が修正案を生成**：CWE/OWASP に沿った修正を脆弱性ごとに。Cloud Run の**サービスアカウント認証（鍵レス）**で呼ぶ。
- **2モード**：**修正案**（コード非開示の対象＝対策方針のみ）／**自律修正**（実ソース書換、または対象の安全な実装に切替えて防御を証明）。
- **自律実行**：開始を押すと全脆弱性を巡回し、最後にレポートを一括提示。
- **合法性の担保**：攻撃は許可リスト（完全一致）の対象のみ。任意URLは 403 で弾き、踏み台にならない。
- **9種の脆弱性**（SQLi/XSS/認証/アクセス制御/設定ミス/パストラバーサル/コマンドインジェクション/JWT改ざん/SSRF）をプラグイン方式で。

## 使用した Google Cloud 技術
- **Vertex AI（Gemini 2.5 Flash）**：修正案・対策方針の生成（鍵レス）。
- **Cloud Run**：frontend / agent / target を3サービスでホスティング（ゼロスケール）。
- **Secret Manager**：制御トークン・署名鍵を安全に注入。

## 構成（モノレポ・3層）
| ディレクトリ | 技術 | 役割 |
|---|---|---|
| `target/` | Next.js | 診断対象の EC（NEKO MART）。9脆弱性をプラグイン方式で組込 |
| `agent/` | Python/FastAPI + Vertex AI | 偵察→攻撃→修復→再証明を自律実行、SSE 配信 |
| `frontend/` | Next.js + D3-force | ダッシュボード（侵入マップ・ログ・進捗・レポート） |

## 今後の展望
現状は自己修復ループの**実証デモンストレーター**（検出は既知9種）。任意リポジトリの未知脆弱性まで自動検査する**汎用スキャナ**は今後の課題。偵察のクローラ化と対象設定の外出し（`antibody.config.json`）はその第一歩。
